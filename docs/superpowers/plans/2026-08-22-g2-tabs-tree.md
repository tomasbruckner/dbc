# G2 Tabs & Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Result-tab infrastructure (buffer per tab, cap 10), schema tree panel with speed search and preview/DDL double-click, full-object `SchemaSnapshot` with per-driver catalog queries, "Generate DDL", plus the two buffer follow-ups (byte cap, fallible spill).

**Architecture:** `SchemaSnapshot` grows in dbc-core (GPUI-free) with a shared CREATE-TABLE synthesis helper; each driver fills it from its own catalog. dbc-ui gains a `tabs.rs` (tab strip + per-tab `ResultGrid`/text views) and a `schema_tree.rs` (left panel, flattened-row rendering, speed search). Schema fetch reuses the runner pattern: open → `schema()` → drop, off the UI thread. No persistent connection yet (per-run connections stay; ledgered follow-up).

**Tech Stack:** Rust, GPUI (pinned 907ed09), Arrow, tokio, rusqlite, tokio-postgres.

**Spec:** docs/superpowers/specs/2026-08-22-gui-target-design.md (§1 layout/tree/tabs, §2 row G2, §3 constraints). Follow-ups: docs/superpowers/2026-08-21-phase-3-follow-ups.md (I1, I2, M9).

## Global Constraints

- `dbc-core` never imports GPUI; `dbc-ui` never imports driver crates outside `connect.rs`.
- Errors are values — no `unwrap`/`expect`/panic on DB or user-data paths (I2 exists because the buffer violates this today).
- Read-only/auto-limit/timeout guards from G1 must keep working unchanged; preview queries respect read-only (they are SELECTs) and bypass auto-limit (they carry their own LIMIT 1000).
- Build/test ONLY with explicit `-p` flags; cargo at `%USERPROFILE%\.cargo\bin\cargo.exe`.
- UI strings: Czech sentence-case (`Náhled: {t}`, `Strom schémat`, `Obnovit`), keep `error:` prefix and query-progress statuses as-is (English, G1 convention).
- Colours: root 0x1e1e2e, panel 0x181825, chrome 0x313244, text 0xcdd6f4/0xa6adc8, accent 0xf9e2af (match existing).
- Docker/pg integration tests are `#[ignore]`d; they must compile and be runnable, but G2 acceptance doesn't require Docker.

// schema.rs — all types #[derive(Debug, Clone, PartialEq, Eq, Default)] where Default makes sense
pub struct SchemaSnapshot {
    pub tables: Vec<TableInfo>,        // kind Table | View | MaterializedView
    pub routines: Vec<RoutineInfo>,    // functions + procedures
    pub triggers: Vec<TriggerInfo>,
    pub sequences: Vec<SequenceInfo>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum TableKind { Table, View, MaterializedView }

pub struct TableInfo {
    pub schema: Option<String>,
    pub name: String,
    pub kind: TableKind,
    pub columns: Vec<ColumnInfo>,
    pub indexes: Vec<IndexInfo>,
    pub constraints: Vec<ConstraintInfo>,
    /// Engine-provided source (views: definition; sqlite tables: sqlite_master.sql).
    /// None => UI synthesizes via ddl::synthesize_create_table.
    pub ddl: Option<String>,
}

pub struct ColumnInfo {
    pub name: String,
    pub data_type: String,
    pub nullable: bool,
    pub default: Option<String>,
    pub is_pk: bool,
    /// FK target, filled where the catalog knows it (feeds G4 joined columns).
    pub fk: Option<FkRef>,
}

pub struct FkRef { pub schema: Option<String>, pub table: String, pub column: String }

pub struct IndexInfo { pub name: String, pub columns: Vec<String>, pub unique: bool }

pub struct ConstraintInfo { pub name: String, pub kind: String, pub definition: String }
// kind: "PRIMARY KEY" | "FOREIGN KEY" | "UNIQUE" | "CHECK" | engine string; definition = human-readable body

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RoutineKind { Function, Procedure }

pub struct RoutineInfo {
    pub schema: Option<String>,
    pub name: String,
    pub kind: RoutineKind,
    /// Display signature, e.g. "(integer, text) -> boolean"; empty string ok.
    pub signature: String,
    pub ddl: Option<String>,
}

pub struct TriggerInfo {
    pub schema: Option<String>,
    pub name: String,
    pub table: String,
    pub ddl: Option<String>,
}

pub struct SequenceInfo { pub schema: Option<String>, pub name: String }

Triggers: `tbl_name` column → `table`. Sequences: none (skip; `sqlite_sequence` is internal). Routines: none.
- Replace the `.filter_map(Result::ok)` silent row-drop (M9): map decode errors into a `QueryError` return instead.

### Task 3: Postgres full catalog (dbc-driver-postgres)

**Files:**
- Modify: `crates/dbc-driver-postgres/src/lib.rs` (`schema()`), `crates/dbc-driver-postgres/tests/*` (extend the docker-gated integration test)

**Interfaces:** consumes SchemaSnapshot v2; produces a filled snapshot using these catalog queries (all excluding `pg_catalog`/`information_schema` schemas):
1. Tables+views+matviews with columns in one pass: `pg_class c JOIN pg_namespace n` where `c.relkind IN ('r','v','m')`, joined to `pg_attribute a` (attnum>0, NOT attisdropped) and `pg_attrdef` for defaults (`pg_get_expr(adbin, adrelid)`), `format_type(a.atttypid, a.atttypmod)` as data_type, `a.attnotnull` → nullable. `relkind: 'r'→Table, 'v'→View, 'm'→MaterializedView`.
2. PKs: `pg_index i` where `indisprimary`, unnest `indkey` → mark `is_pk`.
3. FKs: `pg_constraint` contype='f' → per (conrelid, conkey[i]) column: FkRef to (target schema, `confrelid` table, `confkey[i]` column). Single-column mapping is enough (composite FKs: map pairwise by position).
4. Constraints: `pg_constraint` on the table → name, contype mapped to kind ('p'→PRIMARY KEY,'f'→FOREIGN KEY,'u'→UNIQUE,'c'→CHECK), `pg_get_constraintdef(oid)` as definition.
5. Indexes: `pg_index` joined `pg_class` (index name), `indisunique`, column names via `indkey`→`pg_attribute`. Skip primary-key-backing indexes (indisprimary).
6. Views/matviews ddl: `pg_get_viewdef(c.oid, true)` wrapped as `CREATE [MATERIALIZED ]VIEW {qual} AS\n{def}`. Tables: `ddl: None` (UI synthesizes).
7. Routines: `pg_proc p JOIN pg_namespace` — `p.prokind IN ('f','p')` → Function/Procedure, signature from `pg_get_function_arguments(oid)` + (`f` only) ` -> ` + `pg_get_function_result(oid)`, ddl `pg_get_functiondef(oid)` (use `try/catch` per row — functiondef fails for aggregates; skip prokind 'a'/'w').
8. Triggers: `pg_trigger t JOIN pg_class` where NOT tgisinternal → name, table, `pg_get_triggerdef(t.oid)`.
9. Sequences: `pg_class` relkind='S'.
Decode-safety: use `try_get` everywhere per the established driver convention; on row decode failure return QueryError (no silent drops).

**Interfaces:**
- `pub const DEFAULT_CAP_BYTES: usize = 256 * 1024 * 1024;`
- `push(&mut self, batch: RecordBatch) -> Result<(), BufferError>` where `pub struct BufferError { pub message: String }` (Display + Error). Spill triggers when `mem_rows + n > cap_rows` **or** `mem_bytes + batch.get_array_memory_size() > cap_bytes` (track `mem_bytes`, decrement when a batch spills... no — spilled batches leave memory: on spill, the incoming batch goes to disk and `mem_bytes` is untouched; the caps bound what stays in RAM).

- All `.expect()` on spill write AND read paths become value errors: write errors propagate from `push`; read errors (`slot_batch`) return a synthesized error state such that `cell_text` yields `"<spill read error>"` for affected cells (no panic). `slot_batch` becomes `fn slot_batch(&mut self, ix) -> Option<&RecordBatch>`.

- grid.rs copy: no trailing `\n` after the last row.
- Cargo.toml: tempfile only in `[dependencies]`.
